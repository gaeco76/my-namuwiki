1. 개요#

랜덤플레이댄스(Random Play Dance, RPD)는 여러 K-pop 곡의 안무 구간을 무작위 순서로 틀고, 그 곡을 아는 참가자들이 즉석에서 나와 춤을 추는 공연 형식이다. 유튜브에는 길거리·행사장에서 찍은 RPD 영상이 많이 올라온다.

이 문서는 그런 영상에서 '곡마다 몇 명이 나와 춤을 췄는가'를 근사적으로 세는 방법을 정리한다. 사용자가 Grok·Claude와 함께 설계한 도구로, 정확한 인원이 아니라 범위(예: 6–8명)로 결과를 낸다. 추정[1]

2. 집계 방법 (v1)#

2.1. 처리 단계#

  1. 영상 설명/챕터에서 곡 타임스탬프 파싱
  2. 카운트다운 3초 제외
  3. 곡당 8프레임 샘플링
  4. YOLO 사람 박스 검출 (중심·크기·ROI 유지)
  5. 인접 프레임 간 움직임으로 댄서 분류
  6. 평균/최소/최대 출력 — 중앙에서 움직이는 사람만 집계, 가장자리 대기 인원·스태프·원거리 소형 박스 제외

2.2. 실행#

cd kpop-rpd-counter
python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
python main.py --url "YouTubeURL" --meta-only   # 메타/챕터만
python main.py --url "YouTubeURL"               # 실제 추정
python main.py --video clip.mp4 --desc examples/sample_description.txt
python main.py --demo                           # 파서 데모
  • 출력 파일: output/rpd_counts.csv, output/rpd_counts.json
  • 조정 파라미터: margin_x, motion_threshold, samples_per_song, min_box_h_ratio (원거리 안무 시 낮춤)
  • 한계: 챕터/곡명 없으면 --desc 필요
  • 한계: 줌 변화가 motion score에 영향
  • 한계: 개인 ID 추적 없음 → 중복 집계 가능 (향후 ByteTrack 예정)
  • 한계: 향후: 곡명 OCR, 박스 미리보기 저장

3. v2 아키텍처#

v1의 가장 큰 약점은 개인 ID를 추적하지 않아 같은 사람을 여러 번 셀 수 있다는 점이었다. Claude 9월 21일 대화에서 설계한 v2는 ByteTrack으로 사람을 추적해 이 문제를 보완하고, 판단이 애매한 경우만 Jev 판정에 맡긴다. 추정[2]

3.1. 단계#

  1. yt-dlp로 영상·챕터 다운로드
  2. YOLO + ByteTrack으로 사람 검출·추적 (ID 유지 → v1의 중복 집계 문제 보완)
  3. Python으로 움직임·박스 형태 변화·중앙 근접도·등장 지속성 계산
  4. 점수 0.35–0.65 애매 구간만 Jev가 ‘댄서 vs 관객’ 판정
  5. 곡 앞뒤 15% 버리고, 댄서 수의 90퍼센타일을 곡별 인원으로 채택
  6. Claude Code가 실행·디버그·튜닝

3.2. 댄서 점수 가중치#

신호가중치
움직임35%
형태 변화25%
중앙 근접25%
존재 지속15%

합성 테스트 데이터에서 3명·5명 정확히 집계 (실제 영상 검증 결과는 미확인)

3.3. 실행#

python count_dancers.py <URL> --jev --debug-frames   # 출력: runs/<id>/results.md + 디버그 JPG

3.4. 비용·시간 비교#

방식토큰소요 시간
비전 LLM 전체 판독~260k 토큰5–10분
1초 1프레임 LLM~4.5M 토큰30–60분
Claude 파이프라인~40k 토큰15–19분
Jev 판정 파이프라인~30k 토큰13–16분
규칙만 사용0 토큰12–15분

60분·40곡 영상 기준 추정. Jev는 판정 단계를 6–20배 줄이지만 YOLO가 병목이라 전체는 10–20% 단축. 캐시 사용 시 재튜닝은 수초–30초 (원래 12–15분).
